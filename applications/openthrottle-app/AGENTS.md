# openthrottle-app — agent notes

Electron shell around `openthrottle-developer`. Design: [docs/architecture.md](./docs/architecture.md).

## Commands

- `pnpm nx run openthrottle-app:dev` — `install-electron && electron-vite dev`; opens the window. electron-vite reads `path.txt` itself and never triggers electron's lazy binary download, so `install-electron` fetches it first (needs network once after a clean install; a no-op after).
- `pnpm nx run openthrottle-app:build` — `electron-vite build` to `out/` (gitignored, a declared Nx output).
- `pnpm nx run openthrottle-app:package` — stages the traced runtime closure, then `electron-builder --mac` into `dist/release/` (`OpenThrottle.app` + zip, arm64, ad-hoc signed). See [Packaging](#packaging-an-unsigned-macos-build). `--configuration=universal` builds one arm64 + x64 bundle into `dist/release/mac-universal/` (run `pnpm install --frozen-lockfile --cpu=arm64 --cpu=x64` first); see [Release](#release-job).
- `pnpm nx run openthrottle-app:smoke-package` — opt-in smoke test of the **packaged** `.app` (run `package` first; it does not depend on it). `scripts/smoke-packaged-app.ts` ditto's the bundle to a temp dir, starts a stub OT server (`utils/createStubOtServer.ts`: main probes the configured server before it starts the child, and the stub needs no Postgres/Redis), launches the app with an empty env except `OPENTHROTTLE_SERVER_URL` plus a fresh `--user-data-dir`, reads the port from the `listening on` stderr line, then checks `/__shell/health`, `GET /auth` (SSR), `POST /graphql` (proxied, and counted at the stub) and that the embedded server dies with the app. Non-zero exit on any failure; the release job gates on it. Pass a bundle path to test another build; `--configuration=universal` smokes `dist/release/mac-universal/`, and `--configuration=universal-x64` launches its x64 slice under Rosetta (`--arch x64`, `arch -x86_64`). ~15 s native; under Rosetta the first SSR/proxy requests took >10 s on a cold translation cache, and with the machine under load the app printed nothing for 60 s, so x64 runs use `SMOKE_TIMEOUTS_ROSETTA` (boot 240 s, requests 60 s); the app also ignored SIGTERM for 10 s there (the SIGKILL fallback covers it).
- `pnpm nx run openthrottle-app:test-e2e` — opt-in, **local-only** Playwright (`_electron`) smoke suite; see [Smoke e2e](#smoke-e2e-local-only).

## Invariants & gotchas

- **Developer is an `nx.implicitDependencies` entry, not a `package.json` dependency.** That makes `^build` run `openthrottle-developer:build` first without `nx sync` adding an `applications/*` → `applications/*` tsconfig reference, which is always wrong. The developer app is consumed as built output.
- **electron-vite builds main, preload and ONE tiny renderer.** The only `renderer` entry is the connection screen (`src/renderer`, React + `@openthrottle/react-router-shadcn`, no router) built to `out/renderer/`. The product UI is still the Developer app's build; do not grow the renderer into a second app. It has its own `tsconfig.renderer.json` (bundler resolution + DOM, because the source-first shadcn package cannot typecheck under NodeNext); `typecheck` runs both. Its specs are `*.test.tsx` under `__tests__/` with a `// @vitest-environment jsdom` docblock, and `vitest.config.ts` pins `NODE_ENV=test` (the Nx executor can leave `production`, which breaks React's `act`). The `@nx/vitest:test` executor swallows failures silently: debug with `--reporters=default`.
- **The preload must be one CommonJS file** (`out/preload/preload.cjs`): a sandboxed preload cannot be ESM. Main is ESM. Source stays ESM + nodenext, so relative imports carry `.ts` (`nodeEsmEslintConfig` writes them).
- **No `tsconfig.lib.json` / `tsconfig.app.json`.** `tools/nx-plugins/package-typecheck.ts` would infer an emitting typecheck; `typecheck` is hand-declared as `tsc --noEmit`. `typecheck` and `test` do not depend on the Developer build.
- **`vitest.config.ts` is plain `vitest/config`.** `createVitestConfigNode` only resolves under `packages/` or `tools/`.
- `BrowserWindow` web preferences (`contextIsolation`, `sandbox`, no Node integration, `webSecurity`, no webview tag) are the security contract; they live in `src/main/buildWindowOptions.ts` and are unit-tested. The rest of the contract is in [Electron security checklist](#electron-security-checklist).
- **Two main-side entries.** `electron.vite.config.ts` builds `out/main/main.js` (Electron main) and `out/main/server.js` (forked into a `utilityProcess`; hosts the developer production server). `src/main/` holds the pure, injected-dependency logic (`server/createServerSupervisor.ts`, `probeOrigin.ts`, `utils/`); `src/server/` is the child.
- **The child binds first, then imports.** `@openthrottle/react-router-utils` snapshots `APP_URL` & co at import, so `server-entry.ts` binds `127.0.0.1:0`, writes the origin env (`withLocalOrigin`), posts `{ port }` on `process.parentPort`, and only then dynamically imports the developer build. Never hoist that import. `/__shell/health` answers 503 until the handler is mounted; main probes it.
- **Same-origin proxy.** The child sets `API_URL_EXTERNAL` to its own origin and reverse-proxies `/graphql` (HTTP + WebSocket upgrade, `/graphql` only) and `/health` to the OT server (`http-proxy-3`). The OT server's fixed `CORS_ORIGINS` can never list an ephemeral port, so do not "fix" this with a server CORS change or a developer-app change.
- **Supervisor.** Restarts the child exactly once after an unexpected exit, then calls `onFatal` (error page). `stop()` (on `before-quit` / `window-all-closed`) retires the child so its exit never restarts. A single-instance lock is taken in `main.ts`.
- **Mode env vars.** `OPENTHROTTLE_APP_MODE=dev|embedded` forces a mode; unset, `electron-vite dev` (`NODE_ENV_ELECTRON_VITE=development`) loads the developer Vite server (`OPENTHROTTLE_APP_DEV_URL`, default `http://localhost:6020`) with no child, anything else runs the embedded server. A packaged app is always embedded. `OPENTHROTTLE_SERVER_URL` is the OT server (see [Server settings](#server-settings-and-first-run)); `OPENTHROTTLE_DEVELOPER_BUILD_DIR` overrides the developer build location for an UNPACKAGED run only (`utils/resolveDeveloperBuildDir.ts`; a packaged app always uses its own `developer/`); `WORKSPACE_ROOT` is forwarded only when set. Desktop env defaults live in `src/main/data/data.server-env.ts`; never read or copy a `.env` file.
- **Runtime deps are declared here** (`express`, `compression`, `@react-router/express`, `http-proxy-3`, `react-router`): pnpm is strict and the developer app does not declare them.

## Smoke e2e (local-only)

- **Run:** start the OT server (`:6021`, seeded `developer@openthrottle.ai`), then `pnpm nx run openthrottle-app:test-e2e`. It `dependsOn` `build`, launches the built unpackaged app (`OPENTHROTTLE_APP_MODE=embedded`, `OPENTHROTTLE_SERVER_URL`, a throwaway `--user-data-dir`), signs in through the real form, asserts `/dashboard`, then opens the first plan from `/plans`. Credentials default to the seeded user and honour the `OPENTHROTTLE_BOOTSTRAP_USER_EMAIL` / `_PASSWORD` overrides `scripts/bootstrap-default-user.ts` reads.
- **Unreachable server = visible skip, exit 0.** The suite name becomes `SKIPPED, no OT server answered …` (the target passes `--reporter=verbose`, because Vitest swallows console output of a skipped suite). Do not read a skip as a pass.
- **Files:** `tests/e2e/*.e2e.ts` + `vitest.e2e.config.ts`, a separate Vitest config so `test` (`tests/**/*.spec.ts`) never launches Electron. Playwright's library API is used (the workspace catalog has `playwright`, not `@playwright/test`). Knip lists them as workspace entries in the root `knip.jsonc`.
- **Not in CI, deliberately** ([ci-cost.md](../../docs/monorepo/ci-cost.md) checklist): no macOS runner is allowed, and Electron under `xvfb` on `ubuntu-26.04` would be feasible, but the suite also needs a running OT server, Postgres, Redis and a seeded user, none of which CI provides for this project; a new job would buy that infra for a smoke test. The target name `test-e2e` is not referenced by any workflow (CI runs `nx affected` on `lint`/`typecheck`/`test`/`build` etc.), `cache: false`, and it is not part of `test`. Do not add a job without working the checklist.

## Packaging an unsigned macOS build

`package` = `tsx scripts/stage-app.ts` then `electron-builder --mac --publish never --projectDir dist/stage --config ../../electron-builder.yml`. Output: `dist/release/mac-arm64/OpenThrottle.app` and `dist/release/OpenThrottle-<version>-arm64-mac.zip` (+ `.blockmap`, unused until auto-update). `cache: false`: the output is ~300 MB and the tracer reads the pnpm store, which Nx does not hash.

- **electron-builder never sees pnpm's tree.** `scripts/stage-app.ts` builds `dist/stage/` (a gitignored, declared output): `out/` (electron-vite bundles), `developer/{server,client}` (the developer build), a generated `package.json`, and a flat `node_modules`. electron-builder runs with `--projectDir dist/stage`, so every path in `electron-builder.yml` is relative to the stage (`buildResources: ../../build-resources`, `output: ../release`). Running it from the project dir made its pnpm collector fall back to this project's own dependencies and silently ship the wrong closure (no react, no developer server deps).
- **The closure is traced, not deployed.** `@vercel/nft` traces `out/main/server.js` + `developer/build/server/{index.js,assets/*.js}` (`main.js` imports only `electron` and `node:`; the desktop-bridge is bundled). nft reports real paths under `node_modules/.pnpm/<id>/node_modules/<name>/…` plus the dependency symlinks it walked. `scripts/utils/planStageFiles.ts` rebuilds a flat tree npm-style from those links: hoist to the top, nest a second version under the package that needs it (this closure has four such clashes: `debug`, `ms`, `negotiator`, `redux`), then re-simulates Node's lookup for every package and FAILS on any mismatch or on a traced path it cannot place. `node_modules/.pnpm/node_modules/<x>` (pnpm's virtual hoist, an undeclared optional `require`; today `source-map-support`) is skipped and reported, not shipped. A stage dependency list nobody declared is never guessed.
- **Stage `package.json` is generated** (`utils/buildStagePackageJson.ts`): `main`, `type: module`, `dependencies` = the top-level staged packages, `devDependencies: { electron }` (version only, read from the installed electron), and `packageManager: traversal@1.0.0`, which makes electron-builder walk the real stage `node_modules`. That collector throws on a declared dependency the stage lacks, so staged third-party manifests are trimmed of dependencies that are not staged (`utils/trimUnstagedDependencies.ts`; e.g. `@reduxjs/toolkit` -> `@standard-schema/spec`, which no runtime path requires).
- **`.env` never ships (invariant).** The stage is built from an allowlist (`out/{main,preload,renderer}`, `developer/{client,server}`, traced files); `utils/isExcludedFile.ts` refuses any `.env`/`.env.*`, source map, `.gitkeep`, `.npmrc`, and the script re-walks the finished stage and fails if a `.env` is present. `electron-builder.yml` repeats `!**/.env`, `!**/.env.*`, `!**/*.map`. Nothing here reads a `.env`. Never replace the stage with `pnpm deploy`: it copies the developer app's `.env` (secrets) and ~1.1 GB.
- **The one binary is ripgrep's `rg`, staged by hand and asar-unpacked.** `@vscode/ripgrep` 1.18 resolves `@vscode/ripgrep-<platform>-<arch>/bin/rg` (an optionalDependency) by a computed name the tracer cannot follow, and THROWS at import when it is missing; every IDE route loads it through `ide-engine.server`, so until OT plan 333b0695 every IDE route failed in the packaged app. `RUNTIME_RESOLVED_PACKAGES` (`scripts/data/data.stage.ts`) + `utils/findRuntimeResolvedLinks.ts` add the platform package of the staging machine beside the traced dependent; `asarUnpack` lists `node_modules/@vscode/ripgrep-*/bin/rg` (Electron's `execFile` runs it from `app.asar.unpacked`; checked with `ELECTRON_RUN_AS_NODE=1` against the packaged asar: `rg --version` answers). `stage-app.ts --arch <arm64|x64|universal>` (default: the host) picks the targets (`STAGE_ARCH_TARGETS`); `universal` stages BOTH arches' packages into one stage, because `@electron/universal` needs the two halves' `app.asar` to be identical, and ripgrep picks its package by `process.arch` at runtime. `mac.x64ArchFiles` in `electron-builder.yml` lists both `rg` binaries: `@electron/universal` otherwise refuses a single-arch Mach-O that is identical in both halves. pnpm only installs the host's platform packages, so a universal stage fails with an install hint until `pnpm install --frozen-lockfile --cpu=arm64 --cpu=x64` has run. `stage-app.ts` fails if a native or executable file appears that is not in `EXPECTED_NATIVE_FILES`; add its glob to `asarUnpack` in `electron-builder.yml` AND to that list.
- **ESM + static serving work from inside `app.asar`.** Verified by running the packaged app: the `utilityProcess` child imports `developer/server/index.js` and the ESM chunks from the asar, and `express.static` serves `developer/client` from it (200 for `/assets/*.js`, `/worker.js`, `/favicon.png`). No `client/` unpack was needed. The developer build resolves via `resolveDeveloperBuildDir`: packaged = `<app.asar>/developer`.
- **Ad-hoc signed, not Developer-ID signed.** `mac.identity: '-'`. With `identity: null` the fuse flip leaves the main binary linker-signed and the bundle unsealed ("code has no resources but signature indicates they must be present"), and an arm64 Mac SIGKILLs it at launch (exit 137). `hardenedRuntime`/notarization are off. `enableCookieEncryption` stays off until real signing.
- **Icon:** `build-resources/icon-source.png` (512 px, the admin app's brand icon) -> `icon.icns` via `sips` + `iconutil` (sizes 16..512 and @2x; the 1024 slice is upscaled from 512). No source above 512 px exists anywhere in the repo (admin `branding/` tops out at 512); replacing it needs a real 1024 px asset (OT plan 333b0695, BLOCKED task). Regenerate: write an `icon.iconset` with `sips -z <n> <n> icon-source.png --out icon_<n>x<n>[@2x].png`, then `iconutil -c icns icon.iconset -o icon.icns`.
- **Run it with logs from a terminal:** `OPENTHROTTLE_SERVER_URL=http://localhost:6021 dist/release/mac-arm64/OpenThrottle.app/Contents/MacOS/OpenThrottle --user-data-dir=/tmp/ot-ud --enable-logging=stderr`. The child inherits stdio and prints `[openthrottle-server] listening on http://127.0.0.1:<port>` then `ready`; `curl http://127.0.0.1:<port>/__shell/health` answers `ok`. `--user-data-dir` (a Chromium switch) gives a throwaway profile; there is no separate env override. Kill the main PID (its command line is relative, so `pkill -f <path>` misses it).
- **Size (arm64, 2026-11-13, OT plan 333b0695):** staged `node_modules` 35.6 MB, `app.asar` 37.5 MB (was 40.1), `app.asar.unpacked` 4.5 MB (`rg`), `OpenThrottle.app` 297 MB, zip 124.8 MB (was 123.3: `rg` costs ~1.8 MB zipped, the date-fns trim saves ~0.3). `date-fns` is no longer staged: the developer SSR build bundles it (`ssr.noExternal`), which dropped the `date-fns` + `date-fns/locale` barrels (5.4 MB, ~190 locales for react-day-picker's one `enUS`) for +122 KB of SSR chunk. Biggest staged: `@ts-morph/common` 12 MB (a bundled TypeScript; KEPT on purpose — the IDE symbol routes `ide.symbols`/`ide.symbol` need it, and it is only 2.2 MB zipped, so a desktop build flag that removes them would change developer route behavior for <2% of the download), `zod`, `recharts`, `motion-dom`, `react-dom`. Universal (2026-11-13): `OpenThrottle.app` 528 MB, zip 227.3 MB; `app.asar` is the same 37.5 MB (shared by both halves), only the Electron binaries are lipo-merged. Not shipped: vite, `@react-router/dev`, faker, typescript, rolldown, vitest, eslint, playwright, monaco-editor.
- **New dependency:** `@vercel/nft` (catalog `^1.11.0`; 1.11.1 was inside the 7-day `minimumReleaseAge`).

## Release job

- **`.github/workflows/openthrottle-app-release.yml`** runs on a pushed `openthrottle-app@<version>` tag (it must equal `package.json` `version`; the job checks) or a manual dispatch, on the standard `macos-15` runner. Never on PRs or `main`: cost and rationale in [ci-cost.md § macOS release runner](../../docs/monorepo/ci-cost.md#macos-release-runner-openthrottle-app-releaseyml). Steps: `pnpm install --frozen-lockfile --cpu=arm64 --cpu=x64`, `package --configuration=universal`, `smoke-package --configuration=universal` and `--configuration=universal-x64` (the gates: arm64 natively, x64 under Rosetta), then upload the zip as a 14-day workflow artifact.
- **Not signed or published yet.** The bundle is ad-hoc signed and `CSC_IDENTITY_AUTO_DISCOVERY=false`. Signing + notarization (OT plan 333b0695 tasks 2-3) add `environment: release` (a protected environment holding the Developer ID p12 and the App Store Connect API key); publishing (task 5) goes to GitHub Releases in a dedicated `OpenThrottle/openthrottle-app-releases` repo.
- **Local fallback = the same three commands** from the repo root on a Mac. `workflow_dispatch` only appears once the workflow is on `main`; a tag push runs the tag's own copy of it.

## Server settings and first run

- **Settings file:** `settings.json` in `app.getPath('userData')`, `{ "version": 1, "serverUrl": "<origin>" }`, read/written by `src/main/settings/createSettingsStore.ts` (injected `fs`; writes a temp file then renames). Missing, corrupt or wrong-version reads as "nothing configured", never a throw. The default checkout is a later addition to the same file.
- **Precedence: env `OPENTHROTTLE_SERVER_URL` > `settings.json` > first-run screen.** Whatever is configured is probed first (`serverHealth` over `POST <server>/graphql` in main, `probeOtServer.ts`); no config or a failed probe shows the connection screen (prefilled, with the reason), never a broken window. An env value that is not a valid http(s) URL is ignored. The decision is the pure `utils/decideStart.ts`.
- **Dev mode (`OPENTHROTTLE_APP_MODE=dev` / `electron-vite dev`) skips all of this**: the dev server's own env picks the API, there is no connection screen and no "Change Server…" item. (`electron-vite dev` also serves the renderer, unused there.) Embedded mode loads `out/renderer/`, so it needs a `build` first.
- **Connection screen** is `win.loadFile(out/renderer/index.html)` (a `file:` page, allowed by the fuses; main-initiated loads are not subject to `will-navigate`, page-initiated navigation to `file:` stays blocked). Strict CSP in its `<meta>` (`connect-src 'none'`): the page never touches the network, every call goes through main.
- **Shell bridge vs desktop bridge.** `window.openthrottleShell` (`getSettings`, `testServer`, `saveServer`) is exposed by the one shared preload ONLY when `location.protocol === 'file:'`, so the http-served developer app never gets it. Every handler in `shell/registerShellIpc.ts` re-validates the sender (`security/isShellSender.ts`: top frame, `file:`, exactly the shell page path) and parses its argument with `utils/normalizeServerUrl.ts` (string, http/https, no credentials, reduced to its origin). `window.openthrottleDesktop` is the separate bridge for the developer app (see [Desktop bridge](#desktop-bridge)); never merge the two.
- **Per-server partitions.** The app window uses `persist:ot-<sha256(origin)[0:16]>` (`utils/buildPartitionName.ts`), so each server origin has its own cookies. `http://localhost:6021` and `http://127.0.0.1:6021` are different origins, hence different partitions. Switching back to a server used before reuses its partition and session on purpose; nothing is wiped. Switching (`openApp` in `main.ts`) stops the child, starts one with the new `API_URL_INTERNAL`, creates the new window and only then closes the old one (zero windows would fire `window-all-closed`).
- **Every session needs the permission handlers.** `setPermissionRequestHandler`/`setPermissionCheckHandler` are per session, and an unguarded partition falls back to Electron's allow-by-default. `installSessionGuards(session, …)` takes one session; `installWebContentsGuards` registers the navigation/new-window/webview guards once for all webContents. Partition sessions must come from `createGuardedSessionProvider` (`getGuardedSession(partition)` in `main.ts`), never a bare `session.fromPartition`.
- **The menu is `utils/buildAppMenu.ts`** (pure template builder): standard macOS app-menu roles, File ("Change Server…" hidden in dev mode), Edit (needed so paste works in the URL field), View, Window. Reload / Force Reload / Toggle DevTools appear only when `isDev` (`!app.isPackaged`).
- **WebSocket origin.** The browser's `graphql-ws` socket connects to the child's own origin and `http-proxy-3` forwards the upgrade; the OT server enforces no WS `Origin` check (its CORS list is HTTP only), so any configured server accepts it. `/auth/ws-token` is a developer same-origin route. Unauthenticated, the socket opens and the server closes it `4403`, which is the expected proof of reach.

## Desktop bridge

- **Contract lives in `@openthrottle/openthrottle-desktop-bridge`** (`packages/openthrottle-desktop-bridge`): interface, `DESKTOP_IPC_CHANNELS`, `getDesktopBridge` guard, deep-link mapper. The Developer app reaches it through `@openthrottle/react-router-notifications`; never import it app to app. Surface (v1): `platform`, `version`, `notify`, `openExternal`.
- **Gating is a handshake, not `additionalArguments`.** The window is created before the embedded server picks its port, and the port changes on a child restart, so no origin can be baked into the preload at window creation. The preload instead `sendSync`s `DESKTOP_IPC_CHANNELS.handshake`; main answers `allowed` only when the sender's top frame is on the live `appOrigin`. `file:` pages get `openthrottleShell` only; http(s) pages get `openthrottleDesktop` only if main says so. Main re-validates the sender on EVERY call (`isAppSender.ts`): that, not the preload, is the real guard.
- **Notifications focus rule** (`desktop/createNativeNotifier.ts`): the page's `showSystemNotification` hands the event to the bridge when it exists (skipping the Web API, an explicit stored `enabled: false` still opts out); main shows a native `Notification` only while the window is NOT focused, because the in-app toast already covers a focused window. Clicking one focuses the window and navigates it (`loadURL` on the app origin) to `toPlanRoute(link)`; any link that is not exactly `/plans/<uuid>` only focuses. The `notify` payload is parsed by `parseNotifyInput` (bounded strings). `openExternal` goes through `toExternalUrl.ts` (http/https only).
- **Deep links** (`desktop/createDeepLinkRouter.ts`): `openthrottle://plans/<uuid>` maps to `/plans/<uuid>` via `mapDeepLink` (strict UUID; anything else only focuses). macOS `open-url` is registered before `ready` and queued until the first window exists; Windows/Linux links arrive in `argv` (first launch and `second-instance`). `desktop/decideProtocolRegistration.ts`: a packaged app registers; an unpackaged Windows/Linux run registers `execPath` + app path; an unpackaged macOS run SKIPS (it would hijack the scheme for the bare Electron binary). electron-builder `protocols` writes `CFBundleURLTypes`.
- **Window state** is a separate `userData/window-state.json` (`window-state/`), not part of `settings.json`, so a corrupt file can never lose the saved server. Written debounced on move/resize and synchronously on close, for app/dev windows only (not the connection screen). Restored only if `isBoundsVisible` finds it on a connected display (`screen.getAllDisplays()`).
- **Harness gotcha:** with a custom entry script, do NOT `await` your driver logic at the top level after `import('out/main/main.js')`: Electron defers `ready` until the ESM entry finishes evaluating, so no window ever opens.
