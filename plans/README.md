## Findings considered and rejected

So nobody re-audits them:

- **`reorderPlanTasks` "race condition"** (tasks.resolver.ts:500-506): false positive. Each `Promise.all` callback writes its own fixed `results[index]` and all are awaited before return — no sparse array is possible. The two-pass temp-sort-order is a deliberate unique-constraint-collision avoidance.
- **`plan-output-stream` missing per-plan ownership check** (subscription + `appendPlanOutput`): by design. The resolver is explicitly `@authz-stance: authenticated-only (Path A — OT plan 18e16dfc)`; per-plan ownership was deliberately deferred. Revisit only if multi-tenant isolation becomes a goal (a product decision, not a bug).
- **`ConversationStreamService.controllers` Map "leak"**: speculative. The `runStream` `finally` always deletes the entry; the only non-cleanup path is a hung async iterator, a different problem.
- **CSP-report / Stripe-webhook "no rate limiting"**: already mitigated. `NestjsThrottlerModule` binds a global `GqlThrottlerGuard` as `APP_GUARD`. Only a body-size-limit micro-hardening remains, not worth a plan.
- **Raw SQL in plans.resolver.ts:407-445**: not injectable — interpolates only the constant `MAX_FILTER_FACET_ROWS`, no user input.
- **Comment-only `@authz-stance`**: this is the enforced convention (`resolver-authorization-stance.test.ts` drift gate); auth itself is global via `GlobalAuthGuard`.
- **`personaId` fallback / service-account token-once / payments checkout null-return**: personaId falls back to a fixed map (not injectable); token-once design is sound and prod introspection is already `NODE_ENV`-gated; the payments resolver is dead code (deleted in plan 004).
- **LangChain / devtools transitive CVEs (`undici`, `@nyariv/sandboxjs`)**: real, but they live in the root pnpm catalog / cross-workspace, not the server app — out of scope for this PR. Track separately.
