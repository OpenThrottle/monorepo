## Why this matters

`DevelopmentModule` exposes GraphQL operations meant only for local end-to-end testing from the web app: `developmentPing`, `triggerWebsocketNotification` (emits a test `system.alert`), and `triggerDevJsonlLogSample` (writes sample log lines). It is registered whenever the process is API-like — with **no environment gate** — so in production any authenticated user can invoke these test-only side effects. The module's own doc comment admits "Guards to restrict access (e.g. NODE_ENV checks) are not implemented yet." The app already has the right pattern next door: `NestjsBullmqBoardModule` is registered behind `isBullBoardEnabled()` precisely to keep a dev-only surface out of production. This plan applies the same treatment so dev endpoints are absent in production while remaining available in local/dev (where the schema is generated and the web app uses them).

**Schema safety**: the committed `schema.gql` is generated by booting the server in a non-production environment (`NODE_ENV` unset/`development`). Because the gate below evaluates _true_ in non-production, the module still loads during schema generation, so the dev resolver fields remain in the committed schema and it does NOT change. The gate only removes them from a running **production** process.

## Steps

### Step 1: Add the config helper

Create `applications/openthrottle-server/src/config/development-module.ts`, modeled on the dev-jsonl helper but keyed on `NODE_ENV` so it is safe-by-default in production:

```ts
/**
 * @description Feature gate: the development-only GraphQL surface
 * (DevelopmentModule: ping + test websocket notification + sample JSONL log)
 * is registered everywhere EXCEPT production. Mirrors the isBullBoardEnabled
 * pattern for keeping dev-only surfaces out of prod.
 */
export const isDevelopmentModuleEnabled = (): boolean =>
  process.env.NODE_ENV !== 'production';
```

**Verify**: `pnpm nx run openthrottle-server:typecheck` → exit 0.

### Step 2: Add a test for the helper

Create `applications/openthrottle-server/src/config/development-module.test.ts`, modeled structurally on `src/config/process-role.test.ts`. Cover: returns `false` when `NODE_ENV === 'production'`; returns `true` when `NODE_ENV` is `'development'`, `'test'`, or unset. Save and restore `process.env.NODE_ENV` around each case.

**Verify**: `pnpm nx run openthrottle-server:test -- development-module` → the new test file passes.

### Step 3: Gate the registration in app.module.ts

Import the helper (alongside the other config imports) and change line 204 from:

```ts
    ...(isApiLike ? [DevelopmentModule] : []),
```

to:

```ts
    ...(isApiLike && isDevelopmentModuleEnabled() ? [DevelopmentModule] : []),
```

Do not move the line; keep it exactly where it is in the import list.

**Verify**: `pnpm nx run openthrottle-server:typecheck` → exit 0.
