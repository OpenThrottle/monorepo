# @openthrottle/openthrottle-product

The typed source of truth for how OpenThrottle describes itself. It holds two layers that change at different speeds:

- **Positioning canon** (`PRODUCT_POSITIONING`, `src/data/data.positioning.ts`): the tagline, lede and four pillars, each in short (≤60 chars), medium (≤160) and long forms. Changes quarterly, and only by a human.
- **Feature registry** (`PRODUCT_FEATURES`, `src/data/data.features.ts`): one entry per capability, a discriminated union on `status`. Changes weekly.
- **Project list** (`PRODUCT_PROJECTS`, `src/data/data.projects.ts`): the workspace projects and their maturity (`stable`, `experimental`, `planned`) for the org profile's status table. Nx tags carry no maturity signal, so it is declared here; `check-surfaces` fails when a `path` no longer exists.

There is no Markdown source. Every public surface is built from this data, and none of them is ever read back as a source.

## Installation

**pnpm:**

```bash
pnpm add @openthrottle/openthrottle-product
```

Source-first: `exports` point at `./src/index.ts`, there is no `build` target, and the package has no runtime dependencies.

## The registry entry

| Field      | Meaning                                                                                             |
| ---------- | --------------------------------------------------------------------------------------------------- |
| `id`       | Stable kebab-case key. UI layers key icons on it.                                                   |
| `name`     | Display name.                                                                                       |
| `emoji`    | One emoji (a single grapheme) for text-surface headings: the counterpart to UI icons keyed by `id`. |
| `pillar`   | One of the canon's pillar ids: `memory`, `runners`, `history`, `local`.                             |
| `oneLiner` | At most 120 characters.                                                                             |
| `body`     | One short paragraph.                                                                                |
| `status`   | `shipped`, `preview`, `in-flight` or `planned`.                                                     |
| `evidence` | `{ docs, planIds, prs }`: repo-relative doc paths, OT plan UUIDs, `OpenThrottle/monorepo` PRs.      |
| `since`    | ISO date the entry reached its current status.                                                      |
| `public`   | Shown on public surfaces only when the owner has approved the entry.                                |

The types enforce the evidence rule: a `shipped` or `preview` entry needs at least one merged PR, and an `in-flight` or `planned` entry needs at least one plan id. Keep internal detail (telemetry numbers, machine counts, costs) out of the copy.

## Consumers

| Surface                                                                         | How it is built                                                                                                                                |
| ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Website home (`applications/openthrottle-website`)                              | Imported: canon for hero, promise and flow; public `shipped`/`preview` entries for Features; public `in-flight`/`planned` entries for Roadmap. |
| `@openthrottle/react-router-ui` `FEATURES` / `OpenThrottleProductFeatures`      | Imported: public `shipped`/`preview` entries, icons keyed by `id`.                                                                             |
| Root `README.md`, between `<!-- features:start -->` and `<!-- features:end -->` | Generated by `generate-surfaces`, committed. No stats or dates, so it changes only with the registry.                                          |
| GitHub org profile (`OpenThrottle/.github` `profile/README.md`)                 | Generated to `out/org-profile/README.md` (gitignored). Published by a separate, owner-approved PR; the generator never pushes.                 |
| LinkedIn headline, about and featured                                           | Generated to `out/linkedin.md` (gitignored) with a "Last synced" date, then pasted by hand.                                                    |

## Generate the text surfaces

```bash
pnpm nx run @openthrottle/openthrottle-product:generate-surfaces            # README section + out/ files, with live stats
pnpm nx run @openthrottle/openthrottle-product:generate-surfaces --offline  # no network; stats omitted
pnpm nx run @openthrottle/openthrottle-product:check-surfaces               # the drift gate (CI gates job + check:local)
```

Each renderer in `src/utils/render.ts` is a pure function of `SurfaceInput` (registry, canon, stats, URLs, date). A new output (pitch-deck bullets, a press kit, an `llms.txt`) is a new renderer, never a new source. Stats (merged PRs, package and application counts, supported agent CLIs) are computed at generate time with `gh api`, `nx show projects` and `DRIVER_IDS` from `@openthrottle/openthrottle-drivers`; those two workspace packages are dev-only dependencies of the script.

## Drift gate

`check-surfaces` exits 1 when:

- the root README section differs from what `generate-surfaces` would write;
- the registry breaks a static rule (`validateRegistry`): a `oneLiner` over 120 characters, canon copy over its limits, a duplicate id, an unknown pillar, a malformed `since` or a short plan id;
- a `shipped`/`preview` entry cites a PR that is not merged (via `gh`);
- an `in-flight`/`planned` entry cites an OpenThrottle plan that is `CANCELED` or missing (via `OPENTHROTTLE_GRAPHQL_URL`, default `http://localhost:6021/graphql`, with `OPENTHROTTLE_MCP_AUTH_TOKEN` or `API_TOKEN` from the environment).

The two network checks skip with a warning when `gh` or the API cannot be reached or no token is exported, so CI (which cannot reach the API) never fails on them; `--offline` skips them outright. The script never reads `.env` files for the token.

## Keeping it current

The registry moves forward on its own schedule. [`.agents/prompts/Job_FeatureRegistryRefresh.md`](../../.agents/prompts/Job_FeatureRegistryRefresh.md) is a weekly, read-only audit: it reads the week's landed work (`get_activity_by_date`, merged PRs and their `Plan-Id` footers), decides which changes a user would notice (a new capability, `planned` → `in-flight` → `shipped`, stale wording, moved docs), and files one OpenThrottle plan titled `🏷️ Feature registry refresh: <date>` with the exact `data.features.ts` diff and its evidence, ready for `/ot-loop`. It never edits the registry, never touches the canon and never flips `public`; new entries are proposed private, for the owner to approve.

It runs as an OpenThrottle scheduled job: **Feature registry refresh (weekly)**, provider `claude`, cron `0 9 * * 1` in `America/Los_Angeles`, repository `monorepo` (the primary checkout), with a prompt that points the agent at the file above. Manage it on the developer app's `/schedule` page.

## Usage

```ts
import {
  getFeatureLink,
  getPublicFeatures,
  isUpcomingFeature,
  PRODUCT_FEATURES,
} from '@openthrottle/openthrottle-product';

const roadmap = getPublicFeatures(PRODUCT_FEATURES).filter(isUpcomingFeature);
```
