# Infra tests

Static tests for the Terraform under `infra/`. There is no live `apply`; these
gates run on configuration only, so they need no GCP/Cloudflare credentials.

The same gates run in CI via
[`.github/workflows/terraform-validate.yml`](../../.github/workflows/terraform-validate.yml)
on any change under `infra/**`.

## Gates

| Gate                 | Tool                | What it catches                                                            |
| -------------------- | ------------------- | -------------------------------------------------------------------------- |
| `terraform fmt`      | Terraform           | Formatting drift.                                                          |
| `terraform validate` | Terraform           | Syntax, references, provider-schema errors (per root, `-backend=false`).   |
| `tfsec`              | tfsec               | Broad static security misconfiguration scan.                               |
| Conftest policies    | Conftest / OPA Rego | OpenThrottle-specific security invariants (see `policy/security.rego`).    |
| Provider contract    | bash + awk          | GCP and Hetzner application modules staying interchangeable.               |
| Rendered shell       | shellcheck          | Escaping bugs in the cloud-init template, which only appear once rendered. |

The Conftest policies in [`policy/security.rego`](policy/security.rego) encode the
specific issues from the infra audit so a regression fails CI:

1. Cloud SQL must not use `ssl_mode = "ALLOW_UNENCRYPTED_AND_ENCRYPTED"`.
2. Cloud SQL `authorized_networks` must not include `0.0.0.0/0`.
3. A Terraform **state** bucket (`*-terraform-state`) must enable object versioning.
4. Storage buckets must set `uniform_bucket_level_access = true`.
5. An `hcloud_firewall` must not expose SSH (22) to `0.0.0.0/0` or `::/0`.
6. An `hcloud_firewall` must not open 5432 or 6379 **at all**.
7. An `hcloud_server` must not set `backups = false`.

Rules 1-4 are GCP-shaped and cannot match hcloud resources. Rules 5-7 exist because that asymmetry
is a hazard: without them a Hetzner box with an open firewall would pass this gate simply because no
rule mentioned it.

**Limitation.** Conftest evaluates HCL statically, so it only sees _literal_ values. A rule written
as `source_ips = var.ssh_allowed_cidrs` is invisible, and so are rules generated by a `dynamic`
block — which is how `modules/hcloud_server` writes its own. So 5-7 guard a hand-written resource
with hardcoded values, while the module's own safety comes from variable `validation` blocks
(`ssh_allowed_cidrs` rejects `0.0.0.0/0`). Two mechanisms, not one mechanism twice.

## Other gates

- [`contract/check-provider-contract.sh`](contract/check-provider-contract.sh) — fails if the shared
  variable set drifts between the two application modules, if a shared variable's type diverges, or
  if a provider-specific variable is added without being documented in
  [`../provider-contract.md`](../provider-contract.md).
- [`exposure/verify-exposure.sh`](exposure/verify-exposure.sh) — **not** a static gate. Run against a
  _deployed_ box, from off the box, to assert 80/443 are reachable while 5432/6379 are refused. Used
  by [`../applications/openthrottle_hcloud/CUTOVER.md`](../applications/openthrottle_hcloud/CUTOVER.md)
  and by the post-deploy step of `.github/workflows/hetzner-deploy.yml`.

## Layout

- `policy/security.rego` — the policies.
- `policy/security_test.rego` — Rego unit tests run by `conftest verify`.
- `fixtures/cloud_sql_postgres_secure/` — a secure module-usage example that
  doubles as a `terraform validate` smoke target and a policy fixture that MUST pass.

## Run locally

Install Conftest (`brew install conftest`) and Terraform, then from the repo root:

```bash
# Validate every Terraform root (per-root, no backend credentials).
for dir in $(find infra -type f -name '*.tf' -exec dirname {} \; | sort -u); do
  terraform -chdir="$dir" init -backend=false -input=false
  terraform -chdir="$dir" validate
done

# Unit-test the policies against their own fixtures.
conftest verify --policy infra/tests/policy

# Run the policies over the real Terraform roots + the example fixture.
conftest test --policy infra/tests/policy \
  infra/environments infra/modules infra/applications infra/tests/fixtures
```
