## 2. Prioritization (audit order)

Priority is based on: (1) **root/workspace dependency** — packages depended on by the root `package.json` are used across the monorepo; (2) **cross-package dependency** — packages that other workspace packages depend on (shared infra); (3) **scope size and activity** — larger or more central scopes first; (4) **visormatt** — noted in `packages/README.md` as candidate for archiving, so lower priority.

### Tier 1 — High (shared / root-depended; audit first)

These are depended on from the root `package.json` or by many other packages. Stale READMEs here affect the most consumers.

- **openthrottle:** `mcp-developer`, `nestjs-repositories`, `nodejs-graphql`, `notifications`, `react-router-*` (auth, chat, editor, graphql, profiling, ui, utils)
- **mattscholta:** `ai-mcp`, `docs-mcp`, `graphql-codegen`, `nestjs-*` (auth, bullmq, bullmq-board, devtools, express, graphql, langchain, modules, profiling, rbac, redis, tester, throttler, typeorm, utils, websockets, worktrees), `react-native-*`, `react-router-graphql`, `react-router-shadcn`, `utils`
- **rocketcms:** `core`, `editor`, `library`, `shared-ui`, `supabase`, `surveys`, `tailwind-ui`, `telemetry`
- **barguide:** all 14 packages (root depends on all)
- **intouch:** all 3 packages (root depends on all)

**Suggested order within Tier 1:** openthrottle → mattscholta → rocketcms → barguide → intouch (aligns with OpenThrottle/Cortex focus and then app-specific stacks).

### Tier 2 — Medium (dependencies of Tier 1; audit next)

Packages that are not in root but are depended on by Tier 1 packages. Fixing these avoids broken internal links and wrong package names when auditing Tier 1.

- **visormatt:** `react-router-utils` (used by openthrottle/react-router-editor, rocketcms/surveys), `tester`, `tester-child` (used by visormatt/tester)
- **barguide:** `common` (used by barguide/supabase)
- **mattscholta:** `react-router-shadcn` (used by openthrottle/react-router-ui, react-router-profiling)
- **openthrottle:** `nodejs-graphql` (used by openthrottle/mcp-developer), `nestjs-repositories` (used by mattscholta/ai-mcp), `mcp-developer` (used by mattscholta/nestjs-worktrees)
- **mattscholta:** `nestjs-express` (used by mattscholta/nestjs-graphql), `nestjs-modules` (used by mattscholta/nestjs-devtools)

These are mostly already in Tier 1; the only Tier-2-only ones are **visormatt** packages and any package that is only a dependency of others. So Tier 2 is effectively: **visormatt** (all 5) and then any remaining that are not in root but are internal deps.

### Tier 3 — Lower (visormatt; audit last)

- **visormatt:** `react-graphing`, `react-goodies`, `react-router-utils`, `tester`, `tester-child` — root notes “I should just archive most of whats in here”; audit last so that if archiving happens, less rework.

### Root

- **packages/README.md** — Single file; can be audited at the start (to align scope descriptions) or after Tier 1.
