# Audit Checklist: Component Code and Generator Template Usage

This checklist helps auditors and agents **flag** components and artifacts that may need alignment with `.cursor/rules` and `@tools/generators` generator output. It supports the audit plan **Audit component code for rules compliance and generator template usage** (Plan-Id: `d8ec2e70-8a7a-4717-997f-7c890a70147e`).

**Related docs:**

- **[AUDIT_SCOPE.md](./AUDIT_SCOPE.md)** — Which apps, packages, and artifact types are in scope; sample-first vs full audit.
- **[RULES_TO_GENERATORS_MAP.md](./RULES_TO_GENERATORS_MAP.md)** — Which rules apply to each generator; use §2 for per-artifact checks.
- **[AGENT_INPUTS.md](./AGENT_INPUTS.md)** — What to provide to agents (rules, commands, discoverability).

**Optional automation:** A lightweight script can list candidate files for review. See [§ Script: flag candidates](#script-flag-candidates) and `scripts/audit-templates-compliance.ts`.

---

## 1. How to use this checklist

- **Sample-first (recommended):** Pick 2–3 apps and 2–3 packages from [AUDIT_SCOPE.md §1](./AUDIT_SCOPE.md#1-codebases-in-scope). For each in-scope artifact (component, route, service, etc.), run the relevant per-artifact section below. Record passes/fails and any gaps.
- **Full audit:** After sample findings, apply the same checks across all in-scope codebases (optionally using the script to generate a file list).
- **Agents:** When reviewing or creating code, use the checklist to verify alignment before marking a task complete.

## 2. Cross-cutting rules (all artifact types)

Apply these when the artifact is code (not folder-only).

| Check                     | Rule / convention                                                      | How to verify                                                                                                                                                            |
| ------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Generator-first**       | personal-generators.mdc                                                | For **new** code: was a generator used? If one exists, it must be used (see [AGENT_USAGE.md](./AGENT_USAGE.md)).                                                         |
| **Named exports**         | coding/default-exports.mdc                                             | Components, forms, modals, tables, hooks, utils, services use **named** exports. Only route/layout/entry files may use `export default` where the framework requires it. |
| **Naming**                | coding/naming-conventions.mdc                                          | Files: kebab-case (exception: PascalCase for React component files). Components/types: PascalCase; hooks: `use*`; constants: ALL_CAPS; NestJS: kebab-case.               |
| **React import**          | cursor-commands.mdc                                                    | React files use `import * as React from 'react'`.                                                                                                                        |
| **Return types**          | coding/return-types.mdc                                                | Top-level functions declare return types; components (JSX) are exempt.                                                                                                   |
| **Types**                 | coding/import-type.mdc, interface-extends.mdc, readonly-properties.mdc | Use `import type` for types; prefer `interface extends` over `&`; readonly by default.                                                                                   |
| **No Cursor attribution** | no-cursor-attribution.mdc                                              | No "Made with Cursor" or cursor.com links anywhere.                                                                                                                      |

## 3. Per-artifact checklists

Use the row that matches the artifact type. If the artifact could have been generated by a generator, also consider “Would the generator have produced this structure?”

### 3.1 Remix (component, form, modal, route, table)

| Check         | Expected                                                                                                             | How to verify                                                      |
| ------------- | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| **Export**    | Component/form/modal/table: **named** (`export const Name`). Route: **default** for page component only (framework). | Grep for `export default`; allow only in route/layout/entry files. |
| **Naming**    | PascalCase; forms end with `Form`, modals with `Modal`, tables with `Table`.                                         | Filename and export name match convention.                         |
| **React**     | `import * as React from 'react'`.                                                                                    | Presence of that import in .tsx.                                   |
| **Structure** | Component: `(props: NameProps) =>`; form/modal/table similar to generator output.                                    | Compare to `tools/generators/src/generators/remix/files/`.         |
| **Testing**   | personal-general.mdc: component, userEvent, waitFor, describe per branch; mocks from mocks.ts.                       | Test file exists and follows conventions.                          |

### 3.2 React (component, hook, util)

| Check         | Expected                                                                                              | How to verify                                              |
| ------------- | ----------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| **Export**    | **Named** only (`export const Name`, `export const useName`, etc.).                                   | No `export default` in components/hooks/utils.             |
| **Naming**    | PascalCase components/hooks; camelCase utils; kebab-case file names (PascalCase for component files). | naming-conventions.mdc.                                    |
| **React**     | `import * as React from 'react'` in .tsx.                                                             | Grep for import.                                           |
| **Structure** | Component: `(props: NameProps) =>`; hook: `(_options: NameOptions) =>`.                               | Compare to `tools/generators/src/generators/react/files/`. |
| **Testing**   | component, userEvent, waitFor, describe per branch.                                                   | Test file present and style-compliant.                     |

### 3.3 React Native (component, route)

There is **no** `react-native` entry in `tools/generators/generators.json`. If React Native code exists in the future, align with **react** / **remix** rules and [react-native.md](./react-native.md) (status: no generator registered).

### 3.4 NestJS (graphql-service, simple-service, module)

| Check              | Expected                                                                     | How to verify                                 |
| ------------------ | ---------------------------------------------------------------------------- | --------------------------------------------- |
| **Export**         | **Named** for services/modules.                                              | No default export for service/module classes. |
| **Naming**         | **kebab-case** for files and logical names (e.g. `user-profile.service.ts`). | naming-conventions.mdc, nestjs.md.            |
| **Resolvers**      | Return ListResult / PaginatedResult / Result (not raw entity).               | personal-general.mdc.                         |
| **Entity changes** | Backwards compatible; deprecate rather than remove.                          | personal-general.mdc.                         |
| **Testing**        | Mock providers in beforeEach; describe per branch; factories where used.     | personal-general.mdc.                         |

### 3.5 Package / folders

| Check       | Expected                                                          | How to verify                                         |
| ----------- | ----------------------------------------------------------------- | ----------------------------------------------------- |
| **Package** | Created via package generator when adding new packages.           | If new package, was `@tools/generators:package` used? |
| **Folders** | Routing/services folder sets match folders generator; kebab-case. | Structure and naming.                                 |

## 4. Quick flag list (manual or script)

Use these as a short list to **flag** files for deeper review (without fixing):

1. **Default export in non-route/non-layout file** — `.tsx` under `components/`, `global/`, or similar that contains `export default` and is not under `routes/` or `app/routes/` (or equivalent route path).
2. **Missing `import * as React from 'react'`** — React/Remix/React Native `.tsx` that uses JSX but does not have this import.
3. **Naming mismatch** — Form not ending in `Form`, modal not in `Modal`, table not in `Table`; or component file not PascalCase where convention requires it.
4. **Generator-eligible but hand-written** — Artifact in a path and type that matches a generator (e.g. Remix component in `app/global/components/`) but structure or boilerplate doesn’t match generator output (no `NameProps`, different export shape).

The script in §5 can automate (1) and (2) over in-scope directories.

## 5. Script: flag candidates

A lightweight script **lists** files that may need alignment; it does not change code.

- **Location:** `scripts/audit-templates-compliance.ts`
- **Run:** `pnpm run audit:templates-compliance` (or `tsx ./scripts/audit-templates-compliance.ts`).
- **Behavior:**
  - Scans in-scope directories (see [AUDIT_SCOPE.md](./AUDIT_SCOPE.md)) for `.tsx` and (optionally) `.ts` artifacts.
  - **Flags:** (1) `.tsx` files that have `export default` and are not in a route/layout/entry path; (2) `.tsx` files with JSX that lack `import * as React from 'react'`.
  - Prints paths and a short reason (e.g. `default export in component path`, `missing React import`) to stdout for manual review.
- **Output:** Plain list suitable for piping or for feeding into a follow-up audit. No implementation (fixes) in this planning phase.

Use the checklist above to interpret and act on flagged files.
