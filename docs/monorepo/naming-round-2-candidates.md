# Round 2: Additional Naming Candidates (ex-RocketCMS & ex-Cortex)

More ideas for both products, branching out from the first round. Current choices are **EditKit** (ex-RocketCMS) and **VectorKit** (ex-Cortex); this doc adds alternatives if we need to revisit or want backup options. Availability is **not** checked here—run the same availability workflow (X, GitHub org, NPM scope) before shortlisting.

See [naming-criteria-and-availability.md](./naming-criteria-and-availability.md) for criteria and [naming-final-convention-and-choices.md](./naming-final-convention-and-choices.md) for current choices.

---

## ex-RocketCMS (CMS / product) — Round 2

Branching out: studio/hub metaphors, editorial focus, or less literal product names.

| Candidate       | Rationale |
|-----------------|-----------|
| **EditForge**   | Editing + building; aligns with Forge pattern from round 1. Distinct from EditKit. |
| **CopyDesk**    | Editorial “copy desk” metaphor. Short; clear for content teams. |
| **CanvasKit**   | “Canvas” = creative/editing space. Kit pattern. |
| **StudioKit**   | Studio = where content is made. Kit pattern; may contend with “studio” products. |
| **ComposeKit**  | Composing content/copy. Kit pattern; dev-friendly (compose = structure). |
| **Manuscript**  | Evokes long-form content and publishing. Single word; strong brand. |
| **Inkwell**     | Writing/editing metaphor. Distinct; might be available. |
| **TypeForge**  | Typography/content + forge. Niche but clear. |
| **PublishDesk** | Publishing + desk (workspace). Clear purpose. |
| **ContentDesk** | Content + desk. Literal; easy to understand. |

---

## ex-Cortex (plans / knowledge base) — Round 2

Branching out: memory/recall, index, agent-adjacent, or semantic/embedding angle.

| Candidate       | Rationale |
|-----------------|-----------|
| **RecallKit**  | Recall = retrieving knowledge. Kit pattern; evokes memory/search. |
| **IndexKit**   | Index = structure for finding things. Clear for knowledge base. |
| **SemanticKit**| Semantic search/embeddings. On-the-nose for vector stack; slightly long. |
| **MemoryForge**| Memory + building. Good for “knowledge base” angle. |
| **ContextForge**| Context (MCP, LLM) + building. Forge pattern. |
| **AgentKit**   | Plans/tasks as agent tooling. Broad; may overlap with other agent frameworks. |
| **LensKit**    | “Lens” = view into knowledge/context. Short; distinct. |
| **TraceKit**   | Trace = following plans/tasks. Kit pattern. |
| **NotionKit**  | Evokes notes/plans (risk: Notion the product). Check availability. |
| **AtlasKit**   | Atlas = map of knowledge. Strong metaphor; may be taken. |
