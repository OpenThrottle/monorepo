# Review catalog

What to spot in a diff, the one-line fix, and where the rule lives. This is the single list for `ot-code-review` and for the honor-system sweep in [`Job_RulesConformance`](https://github.com/openthrottle/monorepo/blob/main/.agents/prompts/Job_RulesConformance.md). It never restates a rule or its rationale (the delta rule): follow the source link for that. It never covers correctness bugs.

How to use it:

1. Run the checks in [machine-checks.md](machine-checks.md) first, scoped to the diff. Do not read a diff for those.
2. Read the diff against sections 1 to 6. Review added and changed lines only; legacy code the diff does not touch is not a finding.
3. Cite findings by id (`place-02`, `naming-01`).

Severity:

- `fix before PR`: wrong place or banned folder name, a boundary break, drift from the generator shape, hand-rolling something an existing util or package already does.
- `suggestion`: a naming judgment call, a first duplicate with no existing home, readability calls a reader would make.
- The type-modelling entries (`human-01`, `human-04`, `human-05`) escalate to `fix before PR` when the code is a typed boundary: a resolver, a loader, or a package's public API.

Entry fields: `Spot` (what to see in the diff), `Fix`, `Check` (the machine-check path), `Source` (link keys are defined at the bottom of this file). Machine-check path vocabulary: `lint` (an existing rule), `generator` (regenerate and diff), `audit` (an existing `audit:*` or `check:*` script), `candidate lint` / `candidate audit` (nothing exists today; this is where a future check would go), `honor system` (stays a human call, with the reason).

## Spot to id

- Place: `place-01` banned folder, `place-02` off-vocabulary folder, `place-03` per-area folders, `place-04` premature promotion, `place-05` cross-area import, `place-06` config vs data, `place-07` inline copy, `place-08` test naming, `place-09` re-export-only index, `place-10` stray stories, `place-11` edited generated tree, `place-12` NestJS constant in utils.
- Exemplar: `exemplar-01` not generator-shaped, `exemplar-02` wrong generator, `exemplar-03` React import, `exemplar-04` props unpack, `exemplar-05` return types, `exemplar-06` route shape, `exemplar-07` package skeleton, `exemplar-08` missing spec, `exemplar-09` generator command prefix.
- Humans: `human-01` bag of optionals, `human-02` intersection types, `human-03` readonly, `human-04` optional properties, `human-05` throw vs result, `human-06` self-evident JSDoc, `human-07` missing `@public`, `human-08` let/var, `human-09` promise chains, `human-10` unsorted arrays, `human-11` dense expressions, `human-12` needless `as const`, `human-13` missing waitFor, `human-14` test branches, `human-15` copy assertions, `human-16` JSDoc prose placement.

## 1. Place: everything has one right folder, name and shape

- **place-01** · fix before PR — Spot: A directory named `lib`, `helpers`, `common`, `shared` or `misc` is added, or a file moves into one. Fix: Use the vocabulary word (`utils`, `config`, `data`); cross-area code goes up the ladder. Check: audit: `pnpm run check:local:folder-vocabulary` Source: [of-the-four-standing-rules]
- **place-02** · fix before PR — Spot: A new folder outside the vocabulary (`actions components config data hooks testing types utils`), or a vocabulary folder in the wrong bucket (`components/` or `hooks/` in `nestjs-*` or `nodejs-*`, `actions/` outside an area). Fix: Use a vocabulary word, or move the code to the bucket that owns it. Do not invent a folder. Check: audit: `pnpm run check:local:folder-vocabulary` checks top-level `src/` folders of `packages/*` and `tools/*` per bucket (nodejs, react, react-router), with legacy folders grandfathered in `GRANDFATHERED_FOLDERS`; nested folders, the `nestjs` bucket and `applications/` stay honor system. Never add a grandfather entry to pass it. Source: [of-technology-buckets], [of-the-four-standing-rules]
- **place-03** · fix before PR — Spot: `app/global/` gains `actions/`, `testing/` or `types/`; an area loses one of its eight folders; a `.gitkeep` or empty placeholder folder is deleted. Fix: Actions, testing and types stay per area (`app/testing/`, `app/types/` app-wide). Restore the folder. Check: generator: the `folders` generator emits the canonical subtree. Source: [of-the-promotion-ladder], [of-the-four-standing-rules]
- **place-04** · fix before PR — Spot: Code newly placed in `app/global/` or `packages/` that has one consumer (promotion in anticipation). Fix: Keep it in the one `app/routing/<area>/`; promote when the second consumer appears. Check: honor system: consumer counts need the import graph. Candidate audit: count importing areas per `app/global/` file. Source: [of-the-promotion-ladder]
- **place-05** · fix before PR — Spot: `app/routing/<a>/` imports from `~/routing/<b>/`. Fix: Promote the shared piece to `app/global/<vocabulary>/`. Check: honor system. Candidate lint: `no-restricted-imports` on cross-area `~/routing/*` paths. Source: [of-the-promotion-ladder]
- **place-06** · suggestion — Spot: Tunables, defaults or constants in `data/`, or mock or hard-coded data in `config/`. Seen in review: `routing/plans/data/data.output-stream-attempt.ts` ([PR #734](https://github.com/OpenThrottle/monorepo/pull/734#discussion_r4546659022)). Fix: Constants and defaults go to `config/`; static or mock data to `data/`. Check: honor system: the split is a judgment about what a value is. Source: [of-the-folder-vocabulary]
- **place-07** · fix before PR — Spot: User-facing copy, lists or mock data written inside JSX or a component body instead of the area's `data/`. Includes a sentence assembled from English fragments inside a component body (`` `${a} and ${b}.` ``), and a copy key added to `data.copy.ts` that the same diff never uses while hardcoding the same text. The audit sees module-scope values and exports, not copy written inline in JSX. Fix: `data/data.copy.ts`, `data/data.<name>.ts` or `data/mock.<name>.ts`; the component imports it via `~/routing/<area>/data/…`. Check: audit: `audit:component-shape` R4 and `component-primitive-shape` for module scope and exports; JSX-literal copy stays honor system. Source: [cs-component-and-data-boundaries]
- **place-08** · suggestion — Spot: A test not named for the file it tests (`foo-flow.test.ts` beside `format.ts`), a qualifier placed after `.test`, a bucket's functions split across several test files. Fix: `__tests__/<source-stem>.test.ts`; qualifier between stem and `.test`; one `describe` per function in a bucket's single test file. Check: audit covers the suffix and `__tests__/` placement (`check:local:test-file-names`); the name-matches-source half stays honor system. Source: [cs-testing], [agents-code-style]
- **place-09** · fix before PR — Spot: A new re-export-only `index.ts` (it only imports and re-exports) other than a package's `src/index.ts`, in a package sub-folder or anywhere in an application. An `index.ts` with real code (`utils/index.ts` holding the folder's first utils) is not a barrel and not a finding. Precedent: [PR #720](https://github.com/OpenThrottle/monorepo/pull/720#discussion_r4534564959), [PR #718](https://github.com/OpenThrottle/monorepo/pull/718#discussion_r4534408091), and Matt on PR #986. Fix: Delete it; import the concrete files, and re-export public symbols from `src/index.ts`. Existing barrels (for example `packages/react-router-ide/src/utils/index.ts`) are legacy, so only a new one is a finding. Check: honor system. Candidate audit: an `index.ts` outside a package's `src/` root whose statements are all `export … from` or imports it re-exports. Source: [of-packages-the-barrel-rule], [pkg-agents]
- **place-10** · fix before PR — Spot: `*.stories.tsx` added outside `packages/react-router-shadcn` ([PR #720 comment](https://github.com/OpenThrottle/monorepo/pull/720#discussion_r4534568590)). Fix: Remove the story and its tsconfig include; stories are limited to the shadcn package. Check: honor system. Candidate audit: any `*.stories.*` outside `react-router-shadcn`. Source: [PR #720 review](https://github.com/OpenThrottle/monorepo/pull/720#discussion_r4534568590)
- **place-11** · fix before PR — Spot: A hand-edit to a generated or fanned-out tree: `.agents/skills/`, `.claude/skills/`, per-tool MCP or permission files, committed generator payloads. Fix: Edit `skills/<slug>/SKILL.md` or `.agents/agent-config.json`, then re-sync. Check: audit: `pnpm run check:local:agent-assets`, `check:local:agent-config-parity`, `check:local:generated-attributes`. Source: [agents-contributor-workflow-skills-personas-prompts], [agents-committed-generator-output]
- **place-12** · fix before PR — Spot: NestJS tier: a constant added to `<folder>.utils.ts` when a sibling `<folder>.constants.ts` exists. Fix: Move it to `<folder>.constants.ts`. Check: honor system. Candidate lint: `openthrottle/nestjs-file-exports` could flag a non-function export in a `.utils.ts` when a `.constants.ts` sibling exists. Source: [cs-nestjs-file-names]

## 2. Exemplar: generated code is the shape to match

- **exemplar-01** · fix before PR — Spot: A new component, route, hook, NestJS service or package that does not look like generator output (no props type, wrong folder form, no spec starter) and shows no sign the generator ran. Fix: Regenerate with `@tools/generators`, then port the logic in. If no generator fits, say so before writing custom code. Check: generator: regenerate and diff. Markers, exports and caps are lint; the rest is honor system. Source: [agents-code-style], [cs-generators], [og]
- **exemplar-02** · fix before PR — Spot: The wrong generator for the target: an application-style component under `packages/`, or nesting the generator cannot express (review flagged `react-router-shadcn/src/components/Carousel/useCarousel.tsx` in [PR #718](https://github.com/OpenThrottle/monorepo/pull/718#discussion_r4534638256)). Fix: Package: `react --subGenerator=component --destination=<pkg>`. Application: `react-router --subGenerator=component --application=<app> --folder=<path>`. Flatten to `src/hooks/useX.tsx`. Check: generator: regenerate with the right one. Otherwise honor system. Source: [og-which-one-scaffolds-a-component]
- **exemplar-03** · fix before PR — Spot: A `.tsx` with a default `React` import, a named-only `react` import, or a default export in a component path. Fix: `import * as React from 'react';` and named exports. Check: audit (advisory): `pnpm run audit:templates-compliance`; default exports are a lint error. Source: [cs-general]
- **exemplar-04** · fix before PR — Spot: `props` unpacked after `// Hooks` or after `// 🔌 Short Circuit`, or derived values computed before `// Hooks`. Fix: Identity destructure (and nested identity destructures) before `// Hooks`; derived values under `// Setup`. Check: lint, `warn`: `openthrottle/pre-hooks-unpack`. Source: [agents-code-style], [cs-route-and-component-shape]
- **exemplar-05** · fix before PR — Spot: An exported function or top-level component with no return type. Reverse case: a hand-written return type on a React Router `loader`, `action`, `clientLoader`, `clientAction`, `meta` or `headers` whose result is a plain inferred object ([PR #721](https://github.com/OpenThrottle/monorepo/pull/721#discussion_r4534626454)). Route-module carve-out: a resource route (`resources.*`) and a `loader` or `action` returning `data()` or a `Response` keep their explicit return type (the lint is only `warn` on routes, and the `route-api` template writes `Promise<Response>`); do not flag a typed loader return of that kind. Fix: Add the return type (`React.ReactElement` for components). Leave React Router's inferred exports untyped so typegen flows through, except under the carve-out. Check: lint, `warn`: `@typescript-eslint/explicit-module-boundary-types`. Source: [agents-code-style], [cs-return-types]
- **exemplar-06** · fix before PR — Spot: A route module with missing or out-of-order markers, helpers or data at module scope, or a JSX `const` outside `// Markup` (that last rule is enforced for components only). Fix: Follow the `route` generator output; hoist helpers to `~/routing/<area>/{utils,config,data,hooks}`. Check: lint, `warn`: `openthrottle/route-primitive-shape`; `audit:route-shape:strict` for R1 and R3. JSX-const half is honor system for routes. Source: [cs-route-and-component-shape], [cs-jsx-consts-live-under-markup]
- **exemplar-07** · fix before PR — Spot: A new package missing the generator skeleton: `AGENTS.md`, README listing pnpm first with `pnpm nx run <project>:<target>` examples, `tests/`, the tsconfig trio, a `src/index.ts` barrel, `sideEffects`, `name:` and `publish:` tags. Fix: Generate with the `package` generator and diff against it. Check: audit: `check:local:side-effects`, `nx:validate-tags`, `check:local:package-entrypoints`. README and `AGENTS.md` content are honor system. Source: [of-packages], [agents-code-style], [agent-usage]
- **exemplar-08** · fix before PR — Spot: A new component, hook, util or route with no test, or a generator spec starter left as a stub (`FIXME: should be defined`). Fix: Write the real spec in `__tests__/`. Check: audit (advisory): `pnpm run audit:test-coverage`. Source: [cs-testing]
- **exemplar-09** · suggestion — Spot: A generator command in a script, doc or PR test plan without `NX_ISOLATE_PLUGINS=false` or without the `pnpm nx` prefix. Fix: Add the prefix. Check: honor system: a grep finds it; nothing runs the grep. Source: [cs-generators], [og]

## 3. Humans: write code for a reader

- **human-01** · suggestion (escalates, see top) — Spot: A type with a `status`, `kind` or `type` field beside optional `data`, `error` or variant fields (a bag of optionals). Fix: Discriminated union keyed on the tag. Check: honor system: whether fields belong to one variant is semantic. Candidate lint: none practical. Source: [cs-discriminated-unions]
- **human-02** · suggestion — Spot: `type X = A & { … }`, or any `&` between object types. Fix: `interface X extends A { … }`. Check: honor system. Candidate lint: `no-restricted-syntax` on `TSIntersectionType` with object operands. Source: [cs-interface-extends-over]
- **human-03** · suggestion — Spot: An object type or interface property with no `readonly` that nothing mutates. Fix: Add `readonly`. Check: honor system. Candidate lint: a `readonly`-required selector for type members. Source: [cs-readonly-properties]
- **human-04** · suggestion (escalates, see top) — Spot: `x?: T` on a value callers are meant to supply, or an optional whose omission selects the permissive or default posture (for example `repoAgentConfig?` meaning trusted): escalate to `fix before PR` on a public API. Fix: `x: T | undefined`. Check: honor system. Candidate lint: `TSPropertySignature[optional=true]` outside allowed shapes. Source: [cs-optional-properties]
- **human-05** · suggestion (escalates, see top) — Spot: A new `throw` whose only consumer is a caller's `try`/`catch`, or a new `try`/`catch` wrapped around your own function. Fix: Return a result type (the `_v2` convention). Throwing inside a request handler is fine. Check: honor system: the consumer is in another file. Source: [cs-prefer-results-over-throwing]
- **human-06** · suggestion — Spot: JSDoc that restates a self-evident function (the judgment half; the mechanical half is `human-16`). Fix: Delete it, or keep it only where the behavior is not self-evident. Check: honor system: "not self-evident" is a judgment. Source: [cs-jsdoc-comments]
- **human-07** · fix before PR — Spot: An export that is a package's public API without a `@public` JSDoc tag. Fix: Add `@public`. Check: audit (report only): `pnpm nx run monorepo:knip`. Never `knip --fix`. Source: [cs-jsdoc-comments], [knip]
- **human-08** · suggestion — Spot: `let` that is never reassigned, or `var`. Fix: `const`. Check: lint: `prefer-const`, `no-var` are already `error`; the sweep need not read for it. Source: [cs-general]
- **human-09** · suggestion — Spot: A new `.then()` or `.catch()` promise chain. Fix: `async`/`await`. Check: honor system. Candidate lint: `no-restricted-syntax` on `.then(` call chains. Source: [cs-general]
- **human-10** · suggestion — Spot: An array whose order carries no meaning, left unsorted (object keys are already lint). Fix: Alphabetize it. Check: honor system: the lint covers keys, members and enums only. Source: [cs-alphabetize-arrays-and-object-keys]
- **human-11** · suggestion — Spot: A dense expression a reader has to decode: chained `?.`, `??` and `&&` with side effects, a multi-step `reduce`, a multi-line handler body inline in JSX props. Fix: Name the intermediate values in `// Setup`, or move the handler under `// Handlers`. Check: honor system: lint already covers the named rules (block bodies, ternary length, long strings); the rest is a reader's call. Source: [agents-code-style], [cs-readability]
- **human-12** · suggestion — Spot: `as const` on a value that is already a fixed string or number literal ([PR #720](https://github.com/OpenThrottle/monorepo/pull/720#discussion_r4534581348)). Fix: Drop it. Keep `as const` on objects that replace an enum. Check: honor system. Source: [PR #720 review](https://github.com/OpenThrottle/monorepo/pull/720#discussion_r4534581348), [cs-no-new-enums]
- **human-13** · suggestion — Spot: Async DOM updates asserted without `waitFor` or `findBy*`. Fix: `await component.findBy…` or `waitFor`. Check: honor system: sleeps and timers are lint; a missing wait is not. Source: [cs-testing]
- **human-14** · suggestion — Spot: A test with several `if` branches under one `describe`, or with no edge cases. Fix: One `describe` per branch, plus edge cases. Check: honor system. Source: [cs-testing]
- **human-15** · suggestion — Spot: Assertions on sentence-length copy (`getByText`) or on a literal duplicated from the component; mock data hand-written instead of generated from GraphQL in the app's `mocks.ts`. Fix: Roles, labels, `href`, test ids; or import the constant from `data/data.copy.ts`. Generate mocks. Check: honor system. Candidate lint: `getByText` with a string literal over a length threshold. Source: [cs-testing]
- **human-16** · suggestion — Spot: JSDoc prose that is not behind an inline `@description` tag, or a same-file reference without `{@link}` (the mechanical half of `human-06`). Fix: Move the prose behind `@description` and link with `{@link}`. Check: candidate lint: `eslint-plugin-jsdoc` `require-description` with `descriptionStyle: 'tag'` (not a dependency today); until then, grep the diff for `/**` blocks. Source: [cs-jsdoc-comments]

## 4. Naming: let layout carry context

Mandated forms are never findings: `data.<name>.ts`, `mock.<name>.ts`, NestJS `<folder>.<kind>.ts`, hook `use*.ts`, `.server`, `.client`, `.test`, `.graphql` sidecars. Casing against the export is machine-checked (see the table at the top). Real instances below come from the tree as of this catalog; a new instance in a diff is a regression, an old one is not a finding.

- **naming-01** · fix before PR — Spot: A new file that repeats its folder in its name: `utils/utils.<x>.ts`, `utils/<x>-utils.ts`. Legacy: `applications/openthrottle-developer/app/global/utils/utils.auth.ts` (and six siblings), `applications/openthrottle-developer/app/routing/plans/utils/utils.plans.ts` (folder and area both repeated), `packages/react-router-ui-global/src/utils/utils.global.ts`. The mandated forms (`data.<name>.ts`, `mock.<name>.ts`, NestJS `<folder>.<kind>.ts`) are not findings. Fix: Name it for the subject and let the folder say the kind: `utils/auth.ts`, `plans/utils/format.ts`. Check: honor system. Candidate audit: a file basename that starts with its parent folder's name, minus the mandated forms. Source: [of-naming], [cs-naming-conventions]
- **naming-02** · suggestion — Spot: The kind repeated in the name: `*Hook` or `*Hooks` in `hooks/`, `*Component` in `components/`, `*-config` in `config/`, `*-types` in `types/`, `*-data` in `data/`, `*Action` in `actions/`, `*-utils` in `utils/`. Real: `packages/react-router-cms-core/src/components/CoreNullComponent.tsx`, `packages/openthrottle-ide/src/config/workspace-config.ts`, `applications/openthrottle-developer/app/routing/settings/actions/runMcpConnectorAction.ts`. No `*Hook` file in `hooks/` and no `*-utils.ts` in `utils/` exists today. Fix: Drop the suffix (`CoreNull.tsx`, `workspace.ts`, `runMcpConnector.ts`). "Hook" as a domain word is fine (`usePlanWorkflowConfigHookRow` is about agent hooks). Check: honor system. Candidate audit: basename ends with the singular or plural of its folder name. Source: [of-naming], [cs-naming-conventions]
- **naming-03** · suggestion — Spot: Three or more sibling single-function files sharing a verb or subject. Real: `applications/openthrottle-developer/app/routing/plans/utils/` holds `formatPlanTaskStatus.ts`, `formatPlanScheduledFor.ts`, `formatPlanTagProvenance.ts`, `formatTaskDate.ts`, `formatRunTime.ts` and `formatters.ts`. Fix: One bucket module named for the subject: `plans/utils/format.ts`. Exported identifiers may keep the noun when other areas import them. Merge a generator's output into an existing bucket. Check: honor system. Candidate audit: three or more siblings in one folder with the same verb prefix. Source: [agents-code-style], [cs-naming-conventions], [PR #750](https://github.com/OpenThrottle/monorepo/pull/750)
- **naming-04** · suggestion — Spot: A vague name that says nothing about what belongs: `helpers`, `manager`, `handler(s)`, `misc`, `common`, `shared`, a bare `utils.ts`, `formatters.ts`. Real: `packages/react-router-shadcn/src/components/ContributionHeatmap.helpers.ts`, `applications/openthrottle-developer/app/routing/skills/components/SkillTagVocabularyManager.tsx`, `packages/openthrottle-mcp/src/nest-tool-handlers.ts`, `tools/dotfiles/src/rules/nestjs-file-shared.ts`. Fix: Name the subject. Precedent: [PR #750](https://github.com/OpenThrottle/monorepo/pull/750) split `nodejs-graphql`'s `utils.ts` into `timeout.ts`, `endpoint.ts` and `response.ts`. A banned folder name is `place-01`. Check: honor system. Candidate audit: a name blocklist on basenames (`helpers`, `manager`, `handler`, `misc`). Source: [of-the-four-standing-rules], [cs-naming-conventions]
- **naming-05** · suggestion — Spot: A collection named in the singular, or a singular named in the plural. Seen in review: `fragment-child.entity.ts` for a `children` table ([PR #727](https://github.com/OpenThrottle/monorepo/pull/727#discussion_r4540902430)). Fix: Match the domain noun. Check: honor system. Source: [PR #727 review](https://github.com/OpenThrottle/monorepo/pull/727#discussion_r4540902430)
- **naming-06** · suggestion — Spot: A function not named verb-first (`planStatus` for a formatter), or a function taking more than three positional parameters. Fix: `formatPlanStatus`; pass one options object past three parameters. Check: honor system. Source: [of-naming]
- **naming-07** · suggestion — Spot: Parallel types for the same variant named differently in neighbouring files (`…Ready` vs `…Loaded`, `…Error` vs `…Failed`). Fix: One name, matching the sibling that landed first. Check: honor system. Source: [cs-naming-conventions]

## 5. Duplication: the second copy is a package

- **dup-01** · suggestion (first duplicate, no home) — Spot: The same function, component or constant copied into a second route area of one application. Fix: Promote it to `app/global/<vocabulary>/` and import it from both areas. Check: honor system. Candidate audit: a duplicate-code detector over `app/routing/*`. Source: [of-the-promotion-ladder]
- **dup-02** · fix before PR — Spot: The same code in two applications. An application can never be imported, so the copy is the only way it got there. Fix: Make it a package: extend a `react-router-*` or `nodejs-*` package, or generate a new one with the `package` generator. Check: audit: `nx sync:check` rejects application-to-application references; the copy itself is honor system. Source: [of-the-promotion-ladder], [og]
- **dup-03** · fix before PR — Spot: A hand-rolled helper an existing util or package already provides (formatting, `isRecord` in `@openthrottle/nodejs-utils`, `cn`, driver spawning, GraphQL clients). Fix: Search `packages/*/src/utils` and `app/global/utils` first; import the existing one. "A home" means something exported from a package barrel, or an existing shared `utils` or `config` module whose subject matches. A private same-named helper in another file is not a home: that is a suggestion, and promoting it is out of scope for this PR. Check: lint covers `clsx` and agent CLI spawn only; the rest is honor system. Source: [of-the-promotion-ladder], [agents-code-style]
- **dup-04** · fix before PR — Spot: Hand-rolled UI where `@openthrottle/react-router-shadcn` has a primitive, or a missing primitive added inline in an application. Fix: Use the primitive; add a missing one to `packages/react-router-shadcn/src/components`. Check: honor system. Source: [agents-code-style], [cs-frontend-design]
- **dup-05** · fix before PR — Spot: Raw colors or spacing that bypass the tokens: hex or `rgb()` values, arbitrary Tailwind values such as `text-[#…]` or `p-[13px]`. Fix: The Tailwind and shadcn tokens already in the design system. Check: honor system. Candidate lint: ban arbitrary-value and raw-color classes. Source: [cs-frontend-design]
- **dup-06** · fix before PR — Spot: A per-row actions column built from a `DropdownMenu` overflow, or a new Actions header (`*Table.tsx`, `*-table-columns.tsx`). Fix: `GlobalPopover` with `GlobalPopoverActionsHeader` from `@openthrottle/react-router-ui-global`. Bulk and toolbar bars are a different surface. Check: honor system. Candidate lint: `DropdownMenu` import banned in table-column files. Source: [cs-frontend-design]
- **dup-07** · fix before PR — Spot: Server tests that build repository objects from hand-written `vi.fn()`s ([PR #886](https://github.com/OpenThrottle/monorepo/pull/886#discussion_r4596061976)). Fix: `createBaseRepositoryMock` or the package's `create<Name>RepositoryMock()` from its `./testing` entry. Check: honor system. Candidate lint: object literals of `vi.fn()` typed as a repository. Source: [PR #886 review](https://github.com/OpenThrottle/monorepo/pull/886#discussion_r4605170736), [repos-agents]
- **dup-08** · fix before PR — Spot: A React Router app's test setup, or a `react-router-*` package's hand-written `tests/setup.ts` or `vitest.setup.ts`, re-adding jsdom polyfills, a `window.env` fixture or `afterEach(cleanup)`. Fix: One `setupReactRouterTest({ env: { APP_NAME } })` call from `@openthrottle/react-router-testing`. Check: honor system for the copy; the root cause is the `package` generator's react template, which emits only `tests/.gitkeep` and no `setupFiles`, so the fix is a generator change (see `exemplar.md` § 4). Source: [cs-testing]
- **dup-09** · fix before PR — Spot: A hand-written type or helper that mirrors a GraphQL shape instead of a fragment at the call site (about 25 comments in [PR #946](https://github.com/OpenThrottle/monorepo/pull/946), one in [PR #320](https://github.com/OpenThrottle/monorepo/pull/320)). Fix: A `.graphql` fragment, codegen, and the generated `*Fragment` type at the call site. Check: lint: `openthrottle/prefer-graphql-fragment` catches indexing and aliasing; a hand-mirrored type is honor system. Source: [agents-code-style], [cs-graphql-data-uses-fragment-types]
- **dup-10** · suggestion — Spot: The same user-facing string in a component and its spec, or in two components. Fix: One constant in the area's `data/data.copy.ts`, imported by both. Check: honor system. Source: [cs-testing], [cs-component-and-data-boundaries]
- **dup-11** · suggestion — Spot: The same constant set, string-literal union or type vocabulary defined in two packages (for example `'isolated' | 'trusted'` in both). Fix: Derive one from the other, or have the owning package export it and import it. Escalate to `fix before PR` when the two can drift into a bug. Check: honor system. Candidate audit: identical union members across packages. Source: [of-the-promotion-ladder]
- **dup-12** · suggestion — Spot: Three or more copies of an inline literal or pattern with no home (for example a task href template literal in about 12 places). State the count in the finding. Fix: One builder in `app/global/utils/` (for example `getTaskHref`), imported by every site; for a count of two, see `dup-01`. Check: honor system. Candidate audit: repeated template-literal shapes. Source: [of-the-promotion-ladder]

## 6. Boundaries

- **bound-01** · fix before PR — Spot: A deep import: `@openthrottle/<pkg>/src/…` or `…/dist/…`. Fix: Import the package's main entry; re-export from its `index.ts`. A subpath is fine only when the package's `exports` names it (for example `/testing`). Check: honor system. Candidate lint: `no-restricted-imports` patterns for `@openthrottle/*/src/*` and `@openthrottle/*/dist/*`. Source: [agents-code-style], [cs-where-code-goes], [of-packages-the-barrel-rule]
- **bound-02** · fix before PR — Spot: A new subpath entry in a package's `exports` added to expose one symbol. Fix: Export the symbol from `src/index.ts`. Check: honor system. Candidate audit: diff of `exports` keys per package. Source: [pkg-agents-import-and-export-rules]
- **bound-03** · fix before PR — Spot: A relative import that climbs out of its project, or an import of an application from anywhere. Fix: Import the package by name; shared code becomes a package. Check: lint: `@nx/enforce-module-boundaries`. Source: [of-tags-decide-what-may-import-what]
- **bound-04** · fix before PR — Spot: A new or retagged project with a missing or wrong `type:`, `technology:`, `production:` or `publish:` tag, or with no `name:` tag; a `production:true` project depending on a `production:false` one. Fix: Fix the tags to match what the project is and match its siblings. Check: audit: `pnpm nx:validate-tags` (the `name:` tag is not validated, so check it by eye). Source: [of-enforce-tags]
- **bound-05** · fix before PR — Spot: A tier crossing: `nodejs-*` importing NestJS, React or `react-router`; a `react` bucket package importing `react-router`; components or hooks in a `nestjs` or `nodejs` project. Fix: Move the code to the bucket that owns it. Check: honor system: `technology:` tags are not wired to import rules. Candidate lint: per-bucket `no-restricted-imports`. Source: [of-technology-buckets], [of-packages]
- **bound-06** · fix before PR — Spot: A `node:*` builtin or Node-only package imported (also transitively, through a package barrel) by code a browser bundle reaches. Includes `react-router-ide` importing runtime values from `openthrottle-ide` (types only are allowed). Fix: A `*.server.ts` module plus dynamic import, `import type`, or move the code server-side. Check: audit: `pnpm nx run <app>:check-client-boundary`; lint and typecheck pass when this is broken. Source: [client-node], [pkg-agents-import-and-export-rules]
- **bound-07** · fix before PR — Spot: A source-first package (`packages/react-router-*`, or any with `__build` placeholder targets in `package.json`) gaining a real `build` or `build-package` target, or `main`, `types` or `exports` pointing at `dist/`. Fix: Remove the target. Validate with lint, typecheck and test, then build a consumer app. Check: audit: `check:local:package-entrypoints` catches `exports` conditions into a build dir; the added target is honor system. Candidate audit: extend it. Source: [pkg-agents-source-first-vs-built-how-to-tell], [source-first]
- **bound-08** · fix before PR — Spot: A package that `openthrottle-server` imports without top-level `exports` pointing at `dist/` (only `publishConfig`, or `src`), or a `technology:nestjs` package without live `build` and `dev` targets. Fix: Top-level `exports` to `dist/`; keep the live targets. Check: audit: `check:local:package-entrypoints` for `technology:nestjs`; other server-consumed packages are honor system and fail in the Docker build. Source: [pkg-agents-source-first-vs-built-how-to-tell], [of-packages]
- **bound-09** · fix before PR — Spot: A dependency added to a `package.json` with a hand-typed version instead of `pnpm add` resolving it, `catalog:` or `workspace:^`, or without the matching `pnpm-lock.yaml` change. Fix: `pnpm add <pkg> -w` (catalog) or `"<pkg>": "workspace:^"`, then `pnpm install`. Check: audit: `pnpm run check:catalog`, `pnpm run check:local:lockfile`. A version chosen from memory but valid is honor system. Source: [cs-installing-libraries], [og]
